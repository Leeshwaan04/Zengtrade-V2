Railway Variables — what to add (you are here)

One variable required on service paper-worker:

VARIABLE_NAMEDATABASE_URL
VALUEFull Postgres URI from Supabase (Session · port 5432)

Template — replace YOUR_PASSWORD with your database password, then paste in Raw Editor or the VALUE field:

DATABASE_URL=postgresql://postgres.ponvarxeytfcntckczbn:YOUR_PASSWORD@aws-0-ap-northeast-1.pooler.supabase.com:5432/postgres
  1. Open paper-worker → Variables
  2. Either: type name + value and click Add — or Raw Editor → paste line above → Save
  3. Deployments → Redeploy · logs must show db: supabase

Not sb_secret_ or sb_publishable_ API keys.

Wrong Supabase screen? “Connection pooling → pool size” is not the URI. Use Connect (top of project) or Project Settings → Database → Connection string → URI → Session → 5432. Leave pool size at default (15).

Troubleshooting

  1. Wrong DATABASE_URL — use Supabase Session pooler on port 5432, not Transaction pooler (6543). Worker needs full SQL transactions.
  2. Password special chars — URL-encode @, #, etc. in the DB password.
  3. Logs show db connect retry — wait ~30s; Railway DNS can lag on first deploy.
  4. Heartbeat stale but logs look fine — confirm startup heartbeat ok in logs; re-run /ops gate check.
